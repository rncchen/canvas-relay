# 使用 Canvas Relay

## 工作流程

1. 為目前對話建立穩定且唯一的 ASCII 畫布識別碼，格式使用小寫英數字與連字號，例如 `session-20260804-floor-plan`。同一對話的所有工具呼叫都沿用同一個值。
2. 先呼叫 `canvas_get_scene`，並傳入目前的 `canvasId`。保留既有內容，除非使用者明確要求擦除或清空。
3. 需要理解版面、重疊或手繪內容時，呼叫 `canvas_get_view`。編修階段可保留作者資訊，交付檢視時傳入 `includeAuthors: false`。
4. 批次使用新增或更新工具完成內容，避免逐一元素呼叫。每次修改後再次讀取場景，確認版本、元素數量與座標邊界。
5. 完成後使用 `browser:control-in-app-browser` 開啟 `http://127.0.0.1:4173/?canvas=<canvasId>`。MCP 啟動時會自動帶起瀏覽器伺服器，不要要求使用者另外執行 `npm start`。
6. 在瀏覽器中關閉「作者標籤」，保留「人類繪製」與「AI 繪製」，再置中畫面並檢查裁切、重疊、文字可讀性與整體構圖。
7. 若瀏覽器技能或瀏覽器實例不可用，直接說明未完成實機檢視，不要改用無關工具假裝已驗證。

只有單獨使用瀏覽器畫布、沒有啟動 MCP 用戶端，或 MCP 回報瀏覽器伺服器啟動失敗時，才在專案根目錄執行 `npm start`。

## 工作階段隔離

- 不同對話必須使用不同的 `canvasId`。
- 瀏覽器網址的 `canvas` 查詢參數必須與 MCP 工具的 `canvasId` 完全相同。
- 不要在多個對話中共用 `default`。只有既有安裝未指定識別碼時才使用預設畫布。
- 回覆使用者時可提供目前工作階段的畫布網址，方便直接開啟正確成品。

## 安全限制

- 呼叫任何修改工具前，先讀取場景。
- 未經使用者明確同意，不呼叫 `canvas_clear`。
- 只有指定元素確定要移除時才呼叫 `canvas_delete_elements`。
- 既有元素與修改都保留作者來源，不以複製重建方式改變建立者。
